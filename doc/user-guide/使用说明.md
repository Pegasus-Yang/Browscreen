# browscreen 使用说明

简体中文 | [English](使用说明.en.md)

browscreen 连接外部启动的 Chrome，默认每 300 毫秒采集当前视口。一个采集循环生成完整 PNG，网页、图片接口和 webhook 共用该帧；有有效坐标时，PNG 已包含合成指针。

## 工作目录文件

`.cdp` 是 UTF-8 单行地址，允许 BOM 和末尾换行。支持 Chrome 的 HTTP(S) 调试根入口、浏览器级 WebSocket 及页面级 WebSocket。浏览器级入口选择返回列表中首个已有页面；精确指定页面时写入对应 `/devtools/page/...` 地址。

`.mouse` 是一个文本坐标对，例如 `320,180` 或 `320.5, 180.0`。坐标单位是当前可见视口的 CSS 像素，原点位于其左上角。服务每轮重新读取；空值、缺失、非法、非有限值及视口外坐标使新帧不绘制指针。有效坐标持续显示，直到外部系统改变文件。Chrome 的完整 CSS 视口采用 `window.innerWidth/innerHeight`，与完整视口 PNG 对应；PNG 缩放比例由适配器数据计算。

正常停止或优雅退出会清空已有 `.mouse`，保留文件。同目录重启后，外部写入新坐标即可再次显示指针。运行中的重连和等待超时不会改写 `.mouse`。

## 预览与图片接口

`GET /` 返回只读预览页，按配置间隔依次查询图片，不重叠请求。图片等比缩放，失败时隐藏旧画面。预览页上的鼠标和键盘操作不转发到目标浏览器。

每轮预览读取与图片加载最长等待 5 秒，超时会隐藏旧画面并自动重试。离开页面时取消请求，从浏览器历史缓存返回后自动恢复更新。同一帧重复返回时跳过重复的图片加载；服务重启后帧号变小也能正常更新。

`GET /api/screenshot` 返回最新 `image/png`，包含：

| 响应头 | 含义 |
| --- | --- |
| `Cache-Control: no-store` | 不缓存响应 |
| `X-Frame-Id` | 进程内递增帧编号，重连继续递增 |
| `X-Capture-Started-At` | 本轮采集开始的 UTC 时间 |

无图片时返回 `503` JSON：`waiting_for_browser` 表示等待端点，`screenshot_not_ready` 表示连接成功但首帧尚未产生，`browser_wait_timeout` 表示等待到期，需要重启服务；`capture_failed` 表示采集任务异常停止，需要检查服务日志后重启。

启动或故障恢复的等待预算持续到首个有效图片生成；即使连接成功，连续截图失败也不会重置预算。非法端点可在该预算内修正，服务按配置间隔重新读取。

## 页面悬浮窗示例

已有网页可以用 `iframe` 嵌入服务的预览页，将实时画面固定在页面右下角。先按[安装与运行](../deployment/安装与运行.md)启动 browscreen，确认浏览器可以打开 `http://127.0.0.1:8000/` 并看到持续更新的画面，再将下面代码放在业务页面的 `</body>` 前：

```html
<!-- 修改 src 为当前浏览器可访问的 browscreen 服务根地址。 -->
<iframe
  id="browscreen-preview-window"
  src="http://127.0.0.1:8000/"
  title="browscreen 实时画面（只读）"
  style="
    position: fixed; right: 16px; bottom: 16px;
    width: min(420px, calc(100% - 32px));
    height: min(400px, calc(100% - 32px));
    box-sizing: border-box; z-index: 10000;
    border: 1px solid #d1d5db; border-radius: 8px;
    background: #f3f4f6; box-shadow: 0 4px 20px #0002;
  "
></iframe>
```

只需修改 `src` 的服务地址；`width`、`height` 控制窗口大小，`right`、`bottom` 控制距页面边缘的距离。窗口随页面滚动保持固定位置，小屏幕下尺寸限制在可见区域内。完整 HTML 文件见[实时画面悬浮窗示例](examples/实时画面悬浮窗.html)，修改地址后可用浏览器打开。

窗口内复用服务已有的 PNG 轮询、图片等比缩放、超时重试和不可用状态提示，更新间隔沿用服务的 `--interval-ms` 配置。每次读取的是缓存的最新帧，不会额外触发截图；窗口中的鼠标和键盘操作不控制目标浏览器。

父页面与服务可以使用不同端口或域名，图片请求在预览页内部发往服务自身，因此这个示例无需新增 CORS 配置。接入时注意：

- `127.0.0.1` 指访问网页的用户自己的机器。服务部署在其他机器时，替换为该用户浏览器可访问的服务根地址。
- HTTPS 业务页面接入远程服务时，使用 HTTPS 服务根地址，例如 `https://preview.example.com/`；普通 HTTP 地址可能被[混合内容规则](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)拦截。若浏览器提示[本地网络访问权限](https://developer.chrome.com/blog/local-network-access)，须允许访问才能连接本机或局域网服务。
- 业务页面设置了 CSP 时，需要在 [`frame-src`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-src) 中允许预览服务地址；若同时限制内联样式，将示例中的样式移到业务页面允许加载的 CSS 文件中。

## webhook

使用 `POST /api/webhooks` 注册：

```sh
curl -X POST http://127.0.0.1:8000/api/webhooks \
  -H 'Content-Type: application/json' \
  -d '{"url":"http://127.0.0.1:9001/on-screenshot"}'
```

首次注册返回 `201`，规范化后的重复地址返回 `200`，正文为 `{"url":"http://127.0.0.1:9001/on-screenshot","registered":true}`。记录只在当前进程内保留，重连继续使用，服务重启后重新注册。

每个新帧向注册时生效的唯一地址并发 `POST` 一次。正文为 PNG 二进制，`Content-Type: image/png`，帧编号和开始时间与图片接口一致。接收器直接读取请求 body 即可。

所有发送尝试完成后才进入下一轮采集。单次发送受 3 秒总时间限制；失败记录日志、不自动重试、不跟随重定向。慢接收器会降低实际采集频率，已生成的帧仍逐地址尝试发送。注册不回放历史帧，成功送达不属于发送尝试的保证。

默认日志对同一接收地址的连续失败只在首次输出 WARNING，后续细节保留在 DEBUG；恢复时输出一次 INFO，再次失败重新告警。每帧的实际发送尝试保持不变，开启方式见[命令行参考](../reference/命令行.md)。

## 可选视频录制

安装 `browscreen[video]` 或在源码环境中执行 `uv sync --extra video`，追加项目指定镜像源参数，之后用 `--record` 开启录制：

```sh
uv run --no-sync browscreen --work-dir /absolute/path/to/workspace --record
uv run --no-sync browscreen --work-dir /absolute/path/to/workspace --record \
  --record-output /absolute/path/to/recordings/session.mp4
```

不传 `--record` 时不加载 PyAV、创建录制器或生成文件。缺少依赖但开启录制时，CLI 输出安装提示并以退出码 `1` 结束。完整安装步骤见[安装可选视频依赖](../deployment/安装与运行.md#安装可选视频依赖)。

`--record-output` 指定完整的 `.mp4` 文件路径，后缀大小写不敏感；展开 `~`，相对路径按进程启动目录解析。父目录必须已存在，已有文件不会覆盖，仅提供此参数会报配置错误。未指定时使用系统临时目录生成唯一文件。

视频为 H.264、`yuv420p`、无音轨的 MP4，包含合成 PNG 中的指针。录制复用当前采集结果，不启动额外截图循环。视频从第一张有效帧开始，采用实际采集开始时间确定画面切换；慢采集、编码或 webhook 等待不会被压缩为快速播放。浏览器暂时断开时保留上一张已知画面到恢复或采集结束，这不表示断线期间页面没有变化。

第一张 PNG 的实际尺寸决定视频画布，奇数宽高在右侧和底部补齐至偶数。后续截图尺寸变化时等比例缩放并居中补黑边，保持完整内容；原截图接口尺寸不受影响。编码固定使用 `libx264`、`veryfast` 和 CRF `18`，逐帧等待，不积压或主动丢帧，可能降低实际采集频率及推迟 webhook。

正常结束时，发送 SIGINT 或 SIGTERM 并等待服务退出，完成编码刷新和 MP4 关闭。默认 INFO 日志会输出：

```text
录制完成，视频文件：/absolute/path/to/recordings/session.mp4
```

路径是实际文件的绝对路径，正常视频退出后保留；临时目录之后可能被系统清理，长期保存请指定路径或复制文件。若始终没有有效帧，会删除空文件并输出“未生成视频：未获取到有效截图”。

浏览器恢复超时或采集异常停止时先收尾视频，HTTP 服务仍按原规则工作；服务结束时说明录制提前结束及部分视频位置。运行中发生视频处理或写入错误时，停止录制、尝试收尾并报告错误，截图与 webhook 继续运行。本次运行不自动重启录制。收尾失败会报告残留路径及可能无法播放的结果。SIGKILL、崩溃和强制中断不能保证收尾或输出位置。

安装、启动参数和退出方式见[安装与运行](../deployment/安装与运行.md)，初始服务设计见[设计方案](../design/设计方案.md)，录制设计依据见[可选视频录制实现方案](../design/可选视频录制实现方案.md)。
