# Command-line reference

[简体中文](命令行.md) | [English overview](../../README.en.md)

Installation provides one entry point, `browscreen`. For source installations, use `.venv/bin/browscreen` from the repository root or `uv run --no-sync browscreen`. After activating the environment, use the commands below directly.

## Supported commands

| Command | Behavior | Requires `--work-dir` |
| --- | --- | --- |
| `browscreen --help` / `browscreen -h` | Print commands and options, then exit | No |
| `browscreen version` / `browscreen --version` | Print `browscreen <installed version>`, then exit | No |
| `browscreen --work-dir <directory>` | Start one HTTP service and one capture loop | Yes |

The version comes from installed package metadata and matches the FastAPI OpenAPI version. Version queries do not start the service or read or write exchange files. Use `version` or `--version` to query the version; `-v` enables DEBUG logging.

## Startup options

| Option | Default | Meaning |
| --- | --- | --- |
| `--work-dir` | Required | Existing exchange directory, resolved to an absolute path at startup |
| `--adapter` | `chrome-cdp` | The only currently supported browser adapter |
| `--interval-ms` | `300` | Positive target capture, preview polling, and failed-attempt interval, in milliseconds |
| `--connect-wait-timeout-s` | `60` | Positive, finite budget for startup or recovery through its first valid frame, in seconds |
| `--host` | `127.0.0.1` | HTTP bind address |
| `--port` | `8000` | HTTP port, from `1` to `65535` |
| `-v` / `--verbose` | Disabled | Enable DEBUG diagnostics and HTTP access logs |

Unknown commands, invalid options, or invalid working directories exit with code `2`. Successful help and version queries exit with code `0`.

```sh
.venv/bin/browscreen version
.venv/bin/browscreen --work-dir /absolute/path/to/workspace
.venv/bin/browscreen -v --work-dir /absolute/path/to/workspace --port 8001
```

The `-v` flag can appear before or after startup options. When using uv, place it after `browscreen`, as in `uv run --no-sync browscreen -v --work-dir <directory>`, so it is passed to the service.

## Logging levels

| Event | Default INFO mode | `-v` DEBUG mode |
| --- | --- | --- |
| HTTP startup and shutdown | Retained | Retained with additional diagnostics |
| Initial waiting, first valid frame, recovered image | Once per state change | Same |
| Endpoint waiting, connection failures, capture retries | Repeated details omitted; timeout still warns | Every attempt and its cause |
| HTTP preview and screenshot requests | Omitted | Uvicorn access logging enabled |
| HTTPX, WebSocket, and PNG diagnostics | WARNING and above | DEBUG enabled |
| Consecutive webhook failures | First failure per URL warns; recovery logs INFO; a later failure warns again | Subsequent failed frames log DEBUG |
| Successful `.mouse` cleanup | Omitted | DEBUG |
| Unexpected exceptions or failed cleanup | ERROR with traceback | Same |

Log deduplication does not change retries, waiting budgets, capture intervals, or per-frame webhook delivery attempts. DEBUG logs can contain endpoints, local paths, and protocol contents; remove sensitive data before publishing them.
