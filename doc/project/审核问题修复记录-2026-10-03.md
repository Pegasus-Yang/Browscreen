## 一、修改结果

| 项目 | 实施结果 | 回归覆盖 |
| --- | --- | --- |
| R-02 连续截图失败 | 首个有效 PNG 生成前共用同一恢复截止时间；失败释放连接后按 `interval_ms` 重试；首帧的读取、截图和合成都受预算约束 | 真实 CDP 适配器连接本地 WebSocket，持续返回截图错误或非法 PNG 时按时停止且没有快速重连；验证首帧截图和合成超时、恢复成功及后续独立恢复预算 |
| R-01 非法端点与后台异常 | 捕获 `httpx.InvalidURL` 并归一化为适配器错误；未预期异常立即记录堆栈、清除旧帧、释放连接并返回 `capture_failed` | 非法 IDNA 主机、NUL 字符和不支持的地址格式；修正文件后产图；持续非法地址到期；异常状态、日志与退出清理 |
| R-03 页面恢复轮询 | `pagehide` 取消在途操作、清理定时器和 Blob；持久化 `pageshow` 恢复单一轮询链 | 首次显示不重复请求；请求头、响应体、图片加载期间离开与恢复；旧操作不覆盖新状态；真实 Chrome bfcache 恢复 |
| O-01 预览超时 | 单轮 5 秒预算覆盖获取响应、读取正文和加载图片；超时隐藏旧图并重试 | 三个停滞阶段均能取消、显示超时并恢复；响应体返回 `AbortError` 时仍保留明确的超时原因 |
| O-02 重复帧优化 | 完整消费响应体后，用帧号与采集时间共同判断重复；相同帧跳过 Blob URL 替换和图片加载 | 重复帧不重新加载；时间变化或帧号变小仍更新；缺少帧标识时继续加载；失败恢复后同一帧可以重新显示 |

重复帧优化减少前端图片加载开销，不减少 PNG 网络传输。没有引入新的发送队列、传输协议或依赖。

## 二、接口与运行行为变化

- `--connect-wait-timeout-s` 现在明确覆盖连接到首个有效帧的完整恢复过程，连接成功但持续无法截图不再重置预算。
- 图片接口新增 `503 / capture_failed`，表示后台任务遇到未预期异常并停止。客户端可显示其消息，运维应检查日志后重启。
- 预览读取与图片加载超过 5 秒会隐藏旧图并重试；页面从历史缓存恢复后继续更新。
- Python 运行依赖不变。完整开发测试需要 Node.js 22 或更高版本；缺少 Node 时会明确跳过前端测试，不能将该结果视为完整验证通过。

## 四、真实 Chrome 核验

使用本机 `Google Chrome 154.0.8037.95`，创建独立临时数据目录和本机测试 FastAPI 服务；浏览器及临时目录在脚本结束时回收。截图内容由固定 PNG 测试适配器提供，此轮验证的是实际浏览器中的预览生命周期，不是 Chrome 截图采集端到端验收。

首次尝试在受限沙箱内无法启动 Chrome；在允许启动独立测试浏览器的环境中继续验证。默认生产响应头下，后退页面继续更新，但 `persisted=false`，浏览器报告 `MainResourceHasCacheControlNoStore`、`JsNetworkRequestReceivedCacheControlNoStoreResource` 和 `BrowsingInstanceNotSwapped`。此次运行不算作 bfcache 验证通过，摘录见[默认响应核验](review-fix-evidence/2026-10-03/chrome-default.json)。

随后仅在测试应用中移除缓存限制响应头，并通过不同主机名的本机页面进行导航。实际 `pageshow.persisted=true`，恢复时为第 24 帧，随后增长到第 29 帧，未出现缓存恢复失败事件。生产代码仍保留 `Cache-Control: no-store`。见[真实 bfcache 核验](review-fix-evidence/2026-10-03/chrome-bfcache.json)。

[浏览器核验脚本](review-fix-evidence/2026-10-03/preview-browser-check.py)使用本机 macOS Chrome 路径；`PREVIEW_ALLOW_BFCACHE` 仅影响该测试脚本，不是产品配置。其他系统执行前需调整测试浏览器路径。真实浏览器验证覆盖已完成一帧后的缓存恢复；在途请求三阶段的恢复竞态由上述确定性脚本测试覆盖。
