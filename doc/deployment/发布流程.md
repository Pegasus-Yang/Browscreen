# 发布流程

简体中文 | [English](发布流程.en.md)

本手册以 `0.3.2` 为命令示例，说明本地验证、GitHub Release 和独立 PyPI 发布的顺序。实际线上状态以 GitHub Release、PyPI 官方数据及本地发布记录为准。运行和安装要求见[安装与运行](安装与运行.md)。

## 交付入口与权限

| 操作 | 入口 | 结果 |
| --- | --- | --- |
| 分支提交与 PR | [ci.yml](../../.github/workflows/ci.yml) → [validate.yml](../../.github/workflows/validate.yml) | 完整测试、打包、严格检查、全新安装与 Artifact；仅 `contents: read` |
| 推送 `v*` tag | [release.yml](../../.github/workflows/release.yml) | 按原标签源码验证，消费同次 Artifact，草稿回读一致后公开 |
| 从 main 手动输入已有 tag | GitHub Actions → Release → Run workflow | 可补发早于工作流的原标签，不移动标签；只有发布 job 使用 `contents: write` |
| 上传 PyPI | 本地单独执行，需取得对应发布授权 | 复用已验证 Release 的原始 wheel 与 sdist；Actions 不持有 PyPI 令牌 |

所有外部 Actions 固定到完整提交 SHA。当前基线是 Ubuntu 24.04、Python 3.14、Node.js 22 和 uv 0.13.5；Python 包仍声明 `>=3.14`，未新增上限。本文不自动授予 Git 推送或外部上传权限，默认保留本地提交和附注标签。

## 1. 先准备英文元数据与版本

PyPI 的正文来自发行文件，不会自动随 GitHub README 改变：

```toml
[project]
readme = { file = "README.en.md", content-type = "text/markdown" }
```

简短 `description` 也使用英文，`Documentation` 指向 `doc/README.en.md`；中文 README、中文文档和双语切换继续保留。文档和图片使用公开绝对地址，实际核对状态、类型与内容；不要把本地文件存在当作远程已经可访问。

在合适的版本提交中同步 `pyproject.toml`、`uv.lock` 的 browscreen 版本、`changelog.md` 和使用示例。`pyproject.toml` 是唯一版本来源，CLI 和 OpenAPI 读取安装包元数据，不另写版本常量。修复增加补丁版本；当前英文元数据修复使用 `0.3.2`，不覆盖已发布的 `0.3.1`。

## 2. 本地验证和冻结文件

先按安装说明准备根目录 `.venv`。锁文件当前记录清华默认源；安装仍追加项目约定的阿里云参数，并保留锁文件原默认源，不为历史 tag 重新锁定：

```bash
browscreen_locked_index=$(.venv/bin/python -c "import pathlib,tomllib; d=tomllib.loads(pathlib.Path('uv.lock').read_text()); r={p['source']['registry'] for p in d['package'] if 'registry' in p['source']}; assert len(r)==1; print(r.pop())")
UV_DEFAULT_INDEX="$browscreen_locked_index" uv sync --locked --group dev --all-extras \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -m pytest -q -W error
```

必须有 Node.js 22+ 和可用 PyAV。默认测试使用模拟浏览器端点与 Node 预览生命周期测试，不启动真实 Chrome；不得照搬其他项目的 `-m 'not browser'` 排除条件，也不能把缺少 Node／video 时的跳过视为通过。

```bash
uv build --no-sources --out-dir dist \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv tool run --from 'twine==7.0.0' --with 'readme-renderer[md]==46.0' \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com \
  twine check --strict dist/browscreen-0.3.2-py3-none-any.whl dist/browscreen-0.3.2.tar.gz
```

不要删除保留的旧发行文件，也不要使用 `dist/*` 上传；重复构建时改用新的输出目录。分别检查 wheel `METADATA` 和 sdist `PKG-INFO` 的版本、英文摘要、正文与英文 README、MIT、Python 要求、`video` extra，以及 `preview.html` 和 `assets/cursor.png`。读取正文使用 `get_payload(decode=True).decode('utf-8')`，避免中文语言导航被错误解码。

在源码目录之外创建全新 `.venv` 安装实际 wheel，确认从 site-packages 导入、CLI 版本与帮助、Settings 工作目录和日志参数、OpenAPI 版本与运行资源。基础环境应没有 `av`，开启 `--record` 应返回友好提示和退出码 1；然后为同一 wheel 安装 `[video]`，实际编码并解码短 MP4。CI 的安装检查执行上述步骤；源码环境同步成功不能代替它们。

## 3. 提交、附注标签和 GitHub Release

验证通过后只暂存本次已审核文件，提交信息使用中文。为包含版本和变更记录的提交创建附注标签：

```bash
git tag -a v0.3.2 -m 'browscreen 0.3.2：英文 PyPI 元数据与发布流程'
```

已有标签不得静默移动、覆盖或重命名。获得明确远程推送授权后，推送已审核提交和标签：

```bash
git push origin main
git push origin refs/tags/v0.3.2
```

标签源码必须包含对应版本。普通 CI 和 Release 复用 `validate.yml`；先完整测试、由 sdist 构建 wheel、严格检查并全新安装，随后将同一份文件作为 Artifact 保存 14 天。Release 发布 job 不重新构建，也不执行源码；它核对 manifest、SHA256SUMS 和远端标签，拒绝覆盖已有公开 Release 或草稿，上传草稿后下载附件逐项核验，再公开。

附件为 `.whl`、`.tar.gz`、`SHA256SUMS`、`release-manifest.json`。GitHub 自动生成的 Source code zip/tar.gz 不等于 Python 源码分发包。manifest 区分 `source_commit` 和 `workflow_commit`，记录说明文件、验证范围和 Actions URL；工作流未执行真实 Chrome 验收时会明确注明。

## 4. 从 main 补发历史 tag

默认分支上须已有带 `workflow_dispatch` 的工作流，操作者需要写权限。选择 **main** 运行新版工作流并输入原标签；工作流的代码来自所选运行 ref，检出的项目源码来自该标签。

```bash
gh workflow run release.yml --repo Pegasus-Yang/Browscreen --ref main -f tag=v0.3.1
```

没有 GitHub CLI 时使用 Actions 页面。旧 `0.3.0`／`0.3.1` 标签可保留中文元数据；验证按标签自身的 README 配置核对，不把新版英文规则强加给旧包。历史包上传 PyPI 时不能冒充英文修复版本。已有 Release／草稿时先检查已有状态，不能盲目重试覆盖。

## 5. 下载同一份 Release 文件，单独发布 PyPI

下面的 `gh` 命令需要已安装并登录 GitHub CLI；也可从 Release 页面下载四份附件，或用 GitHub 官方 Releases API 下载。先核对 `SHA256SUMS`、manifest 的标签和源码提交，确认包内为英文说明，再严格检查及全新安装；不要从已改动 README 的 main 重打相同版本。

```bash
browscreen_release_dir=$(mktemp -d)
gh release download v0.3.2 --repo Pegasus-Yang/Browscreen --dir "$browscreen_release_dir"
(cd "$browscreen_release_dir" && shasum -a 256 -c SHA256SUMS)
```

上传前查 `https://pypi.org/pypi/browscreen/0.3.2/json`。不存在时可首次上传；存在时必须比较准确文件列表与摘要。已经上传的文件名不可覆盖，删除后也不能重用；不要移动 tag 或改名旧包绕过。

只读预演不读取真实令牌，不代表权限校验或上传成功：

```bash
env -u UV_PUBLISH_TOKEN -u UV_PUBLISH_USERNAME -u UV_PUBLISH_PASSWORD \
  -u UV_PUBLISH_URL -u UV_PUBLISH_CHECK_URL -u UV_PUBLISH_INDEX \
  uv publish --no-config --dry-run --trusted-publishing never --keyring-provider disabled \
  --publish-url https://upload.pypi.org/legacy/ --check-url https://pypi.org/simple/ \
  "$browscreen_release_dir/browscreen-0.3.2-py3-none-any.whl" "$browscreen_release_dir/browscreen-0.3.2.tar.gz"
```

正式上传须已获授权。`PYPI_TOKEN` 不是 uv 自动读取的变量；仅在发布子进程中映射为 `UV_PUBLISH_TOKEN`。清除其他仓库的用户名、密码、URL/check URL/index 覆盖，并关闭 shell 跟踪，不打印、记录或发送令牌：

```bash
set +x
UV_PUBLISH_TOKEN="${PYPI_TOKEN:?请先在环境中配置 PYPI_TOKEN}" \
  env -u UV_PUBLISH_USERNAME -u UV_PUBLISH_PASSWORD \
  -u UV_PUBLISH_URL -u UV_PUBLISH_CHECK_URL -u UV_PUBLISH_INDEX \
  uv publish --no-config --trusted-publishing never --keyring-provider disabled \
  --publish-url https://upload.pypi.org/legacy/ --check-url https://pypi.org/simple/ \
  "$browscreen_release_dir/browscreen-0.3.2-py3-none-any.whl" "$browscreen_release_dir/browscreen-0.3.2.tar.gz"
```

如需重新加载自己已授权的 shell 配置，先关闭跟踪并抑制配置文件输出；加载后再次关闭跟踪。不要把配置文件内容、令牌或整个环境写入日志。上传中断后先核对官方文件列表，内容相同的已存在文件可以跳过，摘要不同立即停止。

## 6. 按官方 JSON、simple 和实际文件验收

设置下载目录后，在根目录 `.venv` 中执行下段代码。它比较 Release 和 PyPI 的原始文件，不以文件名相同代替摘要一致：

```bash
export BROWSCREEN_RELEASE_DIR="$browscreen_release_dir"
.venv/bin/python - <<'PY'
import hashlib,io,json,os,tarfile,zipfile
from email import policy
from email.parser import BytesParser
from pathlib import Path
from urllib.request import Request,urlopen

folder=Path(os.environ['BROWSCREEN_RELEASE_DIR']).resolve()
manifest=json.loads((folder/'release-manifest.json').read_text())
version=manifest['version'];expected=manifest['files']
assert manifest['release_tag']==f'v{version}'
def request(url,accept='application/json'):
    return Request(url,headers={'User-Agent':'browscreen-release-check','Accept':accept,'Cache-Control':'no-cache'})
with urlopen(request(f'https://pypi.org/pypi/browscreen/{version}/json'),timeout=30) as response:
    published=json.load(response)
info=published['info']
assert info['name']=='browscreen' and info['version']==version
assert info['description_content_type']=='text/markdown'
assert info['project_urls']['Documentation'].endswith('/doc/README.en.md')
assert {item['filename'] for item in published['urls']}==set(expected)
with urlopen(request('https://pypi.org/simple/browscreen/','application/vnd.pypi.simple.v1+json'),timeout=30) as response:
    simple=json.load(response)
indexed={item['filename']:item for item in simple['files']}
output=folder/'from-pypi';output.mkdir(exist_ok=True)
for item in published['urls']:
    name=item['filename'];digest=expected[name]
    assert not item['yanked'] and item['digests']['sha256']==digest
    assert indexed[name]['hashes']['sha256']==digest
    assert item['url'].startswith('https://files.pythonhosted.org/')
    with urlopen(request(item['url'],'application/octet-stream'),timeout=30) as response:
        content=response.read()
    assert hashlib.sha256(content).hexdigest()==digest
    assert content==(folder/name).read_bytes()
    (output/name).write_bytes(content)
    if name.endswith('.whl'):
        with zipfile.ZipFile(io.BytesIO(content)) as archive:
            raw=archive.read(f'browscreen-{version}.dist-info/METADATA')
    else:
        with tarfile.open(fileobj=io.BytesIO(content),mode='r:gz') as archive:
            raw=archive.extractfile(f'browscreen-{version}/PKG-INFO').read()
    metadata=BytesParser(policy=policy.default).parsebytes(raw)
    assert metadata['Version']==version and metadata['Summary']==info['summary']
    assert metadata['Requires-Python']==info['requires_python'] and metadata['License-Expression']=='MIT'
    assert metadata.get_payload(decode=True).decode('utf-8').strip()==info['description'].strip()
    assert info['summary'].isascii() and info['description'].startswith('# browscreen\n')
    assert 'A browser screenshot and mouse pointer preview service.' in info['description']
print(f'Official JSON/simple, both downloads, hashes and English metadata verified: {version}')
PY
```

随后在新的独立目录 `.venv` 中安装 `from-pypi/` 的 wheel，重复基础、`video`、CLI、Settings、资源和短 MP4 检查。保存源码提交、工作流提交、Actions URL、标签、两份文件摘要、上传与回读结果到忽略的 `local/releases/0.3.2/`。

官方 JSON／simple／文件摘要、镜像同步、PyPI 页面正文和实际 Chrome 截图验收是不同层级。阿里云首次同步可能延迟；网页客户端验证页或仅 HTTP 200 不能证明正文展示正确。若网页不可读，明确记录只完成官方元数据与安装验证，不冒称完成视觉验收。

参考：[uv 发布](https://docs.astral.sh/uv/guides/package/)、[PyPI 项目说明](https://docs.pypi.org/project-management/project-descriptions/)、[GitHub 手动运行工作流](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)。
