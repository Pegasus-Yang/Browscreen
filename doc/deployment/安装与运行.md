# 安装与运行

简体中文 | [English](安装与运行.en.md)

browscreen 使用 Python 3.14、项目根 `.venv/` 和 `uv.lock`。浏览器、CDP 地址、工作目录及端口由主服务或测试准备方提供。

## 安装

在项目根目录执行：

```sh
uv venv --python 3.14 .venv
uv sync --locked --group dev \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
.venv/bin/python -V
.venv/bin/browscreen --help
```

已有 Python 3.14 时直接使用；需要安装解释器时先执行 `uv python install 3.14`。项目使用 `src/browscreen/` 打包，安装后从根目录即可导入，无需配置 `PYTHONPATH`。受限执行环境无法写入 uv 默认缓存时，可给上述 uv 命令设置 `UV_CACHE_DIR=/private/tmp/browscreen-uv-cache`。

## 启动

外部系统先准备一个已有工作目录，并将可达 Chrome 调试地址写入固定文件 `.cdp`。例如 `.cdp` 内容为 `http://127.0.0.1:9222`，之后执行：

```sh
uv run --no-sync browscreen \
  --work-dir /absolute/path/to/workspace \
  --adapter chrome-cdp \
  --interval-ms 300 \
  --connect-wait-timeout-s 60 \
  --host 127.0.0.1 \
  --port 8000
```

打开 `http://127.0.0.1:8000/` 查看只读画面。首次尚未提供 `.cdp` 时，HTTP 立即可用，并在 60 秒等待期内持续重读文件。正常连接不主动切换被改写的地址；连接或页面失效后，重新读取 `.cdp` 并进入独立的恢复等待。到期后 HTTP 保留，采集停止；修正文件后重启服务。

每轮等待持续到首个有效 PNG 生成，期间反复连接成功但截图失败不会重置截止时间。收到 `capture_failed` 时，采集任务已因未预期异常停止，查看服务日志中的堆栈、修正原因后重启。

只运行一个 Uvicorn worker。主服务以 SIGINT 或 SIGTERM 正常结束子进程，并等待其退出；此时已有 `.mouse` 保留且内容清空，`.cdp` 保留，Chrome 继续运行。浏览器启动、访问和最终回收由外部系统管理。

## 验证与构建

完整测试需要 Node.js 22 或更高版本运行预览脚本回归，无需安装 npm 依赖。缺少 Node 时，pytest 会明确跳过该项；这种结果不代表前端验证通过。Python 测试使用项目根 `.venv/`。

默认 pytest 使用模拟浏览器端点，不启动真实 Chrome。文档证据目录中的真实浏览器核验脚本需单独执行；本机受限沙箱中的 Chrome 启动曾在 macOS 应用注册阶段崩溃，移出该限制后成功，执行此类核验应使用允许启动 Chrome 的正常环境和独立临时数据目录。

```sh
.venv/bin/python -m pytest -q -W error
uv build --wheel \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
```

wheel 包含 `preview.html` 和 `assets/cursor.png`。审核与验收记录及其证据仅在本地保存，不随仓库分发。
