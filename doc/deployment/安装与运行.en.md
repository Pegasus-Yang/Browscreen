# Installation and deployment

[简体中文](安装与运行.md) | [English project overview](../../README.en.md) | [User guide](../user-guide/使用说明.en.md)

browscreen connects to a browser supplied by your host application. The host application provides the working directory and CDP endpoint, starts and navigates Chrome, and manages its eventual shutdown. Run one browscreen process with one Uvicorn worker for each instance.

## Prerequisites

- Python 3.14 and `uv` for the project's `.venv/` environment and locked dependencies.
- An existing Chrome instance with a reachable CDP endpoint and an open page.
- An existing working directory. browscreen must be able to read `.cdp` and `.mouse`, and truncate an existing `.mouse` during graceful shutdown.
- Node.js 22 or later for the full development test suite. Node.js is not needed to run browscreen itself.

The commands below are shell examples to run from the repository root. Replace example paths and ports with those managed by your application.

## Install from source

If Python 3.14 is not available, install it with:

```sh
uv python install 3.14
```

Create the environment and install the locked runtime dependencies:

```sh
uv venv --python 3.14 .venv
uv sync --locked --no-dev \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
.venv/bin/python -V
.venv/bin/browscreen --help
.venv/bin/browscreen version
```

The package uses the `src/browscreen/` layout. Installation makes imports work from the repository root; no `PYTHONPATH` or editor source-root configuration is required. The commands use the project's designated Aliyun package mirror.

If a restricted environment cannot write to the default uv cache, set `UV_CACHE_DIR` to a writable directory when running uv. For example, on macOS:

```sh
UV_CACHE_DIR=/private/tmp/browscreen-uv-cache uv sync --locked --no-dev \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
```

## Prepare and start an instance

Your host application must first prepare the working directory and browser. A Chrome HTTP debugging root such as `http://127.0.0.1:9222` can be written as the single line in `.cdp`:

```sh
work_dir="/absolute/path/to/workspace"
printf '%s\n' 'http://127.0.0.1:9222' > "$work_dir/.cdp"
uv run --no-sync browscreen \
  --work-dir "$work_dir" \
  --adapter chrome-cdp \
  --interval-ms 300 \
  --connect-wait-timeout-s 60 \
  --host 127.0.0.1 \
  --port 8000
```

Open `http://127.0.0.1:8000/`. The service provides HTTP immediately, even if `.cdp` is initially missing or the browser is not ready. Endpoint formats and target selection are described in the [user guide](../user-guide/使用说明.en.md#browser-endpoint-cdp).

Installation provides one `browscreen` entry point. See the [command-line reference](../reference/命令行.en.md) for help, version queries, and all startup options. Default INFO logs retain state changes, timeouts, and errors while omitting repeated retries and individual requests. Add `-v` or `--verbose` after `browscreen` to enable DEBUG diagnostics and HTTP access logs.

Separate instances need separately managed browser endpoints, working directories, and HTTP ports. browscreen does not create or isolate Chrome instances.

## Recovery and shutdown

A startup or recovery budget includes endpoint waiting, connection, and creation of the first valid PNG. Successful connection attempts followed by repeated screenshot failures do not reset it. After producing a valid frame, a later browser failure starts a new recovery cycle. Failed attempts respect `--interval-ms`.

During recovery, the latest image is cleared and `.cdp` is reread. You can correct the address while the budget remains. A healthy connection does not switch targets merely because the file changes. When the budget expires, capture and endpoint polling stop while HTTP stays available; correct the problem and restart browscreen.

An unexpected capture-task exception clears the image and returns `503` with `code: "capture_failed"`. Inspect the logged traceback, address the cause, and restart the service.

For normal shutdown, stop external pointer-file updates, send SIGINT or SIGTERM to the browscreen process, and wait for it to exit. The service cancels capture, releases its connections, and truncates an existing `.mouse` to zero bytes. It leaves `.cdp` and the external browser intact. A missing `.mouse` is not created. Forced termination cannot guarantee this cleanup.

## Troubleshooting

| Symptom | Check or action |
| --- | --- |
| Startup rejects the working directory | Create it before startup and pass a directory, not a file |
| `waiting_for_browser` | Check the `.cdp` file, endpoint reachability, and presence of an existing page; correct the file within the waiting budget |
| `screenshot_not_ready` | The browser is connected but no valid frame has been published yet; inspect logs if this persists |
| `browser_wait_timeout` | Correct the endpoint or browser state, then restart browscreen |
| `capture_failed` | Inspect the service traceback and restart after addressing the cause |
| Pointer does not appear | Check the `.mouse` format and that the coordinates are inside the CSS viewport |
| Capture is slower than the configured interval | Check capture/composition duration and webhook response times; the next capture waits for all delivery attempts |
| Chrome exits during separate real-browser verification | Check Chrome's crash report and launch environment; use an isolated temporary browser profile |

The preview UI and runtime messages are currently in Chinese. Use the error `code` field for programmatic handling; English explanations are in the [user guide](../user-guide/使用说明.en.md#screenshot-api).

## Tests and build

```sh
uv sync --locked --group dev \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
.venv/bin/python -m pytest -q -W error
uv build \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
```

Building produces a source archive and a wheel. The wheel includes `preview.html`, `assets/cursor.png`, the CLI entry point, and the MIT license. Runtime logs, exchange files, and local review or acceptance evidence are excluded from distribution.

The standard tests use local simulated browser endpoints and a Node-based preview harness. They do not launch Chrome. If Node.js is unavailable, pytest reports a skipped frontend test; install Node.js to obtain full coverage of that suite. Real-Chrome verification is a separate procedure; the [implementation plan](../design/具体实施方案.md#四本机最终验收操作) contains Chinese instructions for isolated browser checks.

To install a built wheel in a deployment directory, create its `.venv/` and provide the actual wheel path:

```sh
uv venv --python 3.14 .venv
wheel_file="/absolute/path/to/browscreen-0.2.0-py3-none-any.whl"
uv pip install --python .venv/bin/python "$wheel_file" \
  -i http://mirrors.aliyun.com/pypi/simple/ \
  --trusted-host mirrors.aliyun.com
.venv/bin/browscreen version
```
