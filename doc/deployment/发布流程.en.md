# Publishing workflow

[简体中文](发布流程.md) | English

This guide uses `0.3.2` as the command example. Actual publication status comes from GitHub Releases, official PyPI data, and local release records. See [installation and deployment](安装与运行.en.md) for runtime requirements.

## Delivery channels and permissions

| Action | Entry point | Result |
| --- | --- | --- |
| Branch push or PR | [ci.yml](../../.github/workflows/ci.yml) → [validate.yml](../../.github/workflows/validate.yml) | Full tests, builds, strict metadata checks, fresh installations and an Artifact; `contents: read` only |
| Push a `v*` tag | [release.yml](../../.github/workflows/release.yml) | Validate the original tag's source, consume that run's Artifact, verify draft downloads, then publish |
| Dispatch from main with an existing tag | Actions → Release → Run workflow | Backfill a tag that predates the workflow; only the publishing job gets `contents: write` |
| Upload to PyPI | Separately authorized local action | Reuse the verified Release wheel and sdist; Actions does not receive a PyPI token |

External Actions use full commit SHA pins. The current runner baseline is Ubuntu 24.04, Python 3.14, Node.js 22, and uv 0.13.5. Package metadata still declares `>=3.14`, without a new upper bound. This guide does not grant push or upload permission; commits and annotated tags remain local by default.

## 1. Prepare English metadata and the version

PyPI renders distribution metadata; editing GitHub README files does not update an existing PyPI description:

```toml
[project]
readme = { file = "README.en.md", content-type = "text/markdown" }
```

Use an English short `description` and point `Documentation` to `doc/README.en.md`. Keep the Chinese README, guides, and language navigation. Use public absolute document and image URLs, and check their responses and contents rather than only checking local files.

Synchronize `pyproject.toml`, the browscreen entry in `uv.lock`, `changelog.md`, and affected examples in a version commit. `pyproject.toml` is the sole version source; the CLI and OpenAPI read installed package metadata. A fix increments the patch version: the English metadata correction uses `0.3.2`, preserving published `0.3.1` files.

## 2. Validate locally and freeze the files

Prepare the root `.venv` using the installation guide. The lock currently records the Tsinghua default registry. Preserve that registry while adding the project's required Aliyun installation options; never relock historical tags:

```bash
browscreen_locked_index=$(.venv/bin/python -c "import pathlib,tomllib; d=tomllib.loads(pathlib.Path('uv.lock').read_text()); r={p['source']['registry'] for p in d['package'] if 'registry' in p['source']}; assert len(r)==1; print(r.pop())")
UV_DEFAULT_INDEX="$browscreen_locked_index" uv sync --locked --group dev --all-extras \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
.venv/bin/python -m pytest -q -W error
```

Node.js 22+ and a loadable PyAV are required for complete coverage. Default tests use simulated browser endpoints and the Node preview lifecycle harness; they do not launch Chrome. Do not copy another project's `-m 'not browser'` exclusion, or treat missing-Node/video skips as successful coverage.

```bash
uv build --no-sources --out-dir dist \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com
uv tool run --from 'twine==7.0.0' --with 'readme-renderer[md]==46.0' \
  -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com \
  twine check --strict dist/browscreen-0.3.2-py3-none-any.whl dist/browscreen-0.3.2.tar.gz
```

Retain old distributions and never upload `dist/*`. Use a new output directory for another build. Check both the wheel's METADATA and sdist's PKG-INFO: version, English summary and README body, MIT, Python requirement, video extra, preview HTML, and cursor PNG. Decode the body with `get_payload(decode=True).decode('utf-8')` to preserve the Chinese language-navigation label correctly.

Install the actual wheel in a brand-new `.venv` outside the source tree. Verify site-packages imports, CLI version/help, Settings work-directory and logging arguments, OpenAPI version, and runtime resources. The base environment must lack `av`; enabling recording must fail with a friendly message and exit 1. Then install `[video]` from the same wheel, encode a short MP4, and decode it. CI performs these checks; editable source installation is insufficient evidence.

## 3. Commit, annotate the tag, and publish a GitHub Release

Stage only reviewed files after validation and use a Chinese commit message. Create an annotated tag on the version/changelog commit:

```bash
git tag -a v0.3.2 -m 'browscreen 0.3.2：英文 PyPI 元数据与发布流程'
```

Never silently move, replace, or rename an existing tag. Push the reviewed commit and tag only after explicit remote authorization:

```bash
git push origin main
git push origin refs/tags/v0.3.2
```

The tag must match the source version. CI and Release share `validate.yml`: full tests, a wheel built from the sdist, strict metadata checks, and fresh installations produce one Artifact, retained for 14 days. The publishing job does not rebuild or execute package source. It checks the manifest, SHA256SUMS, and remote tag, rejects existing Releases and drafts, uploads a draft, downloads and verifies its assets, then makes it public.

Assets are the wheel, sdist, SHA256SUMS, and release-manifest.json. GitHub's automatic Source code archives are not Python sdists. The manifest distinguishes source_commit from workflow_commit and records the description file, validation scope, and Actions URL. It explicitly states when real-Chrome acceptance was not run.

## 4. Backfill an older tag from main

The default branch must contain the workflow_dispatch-enabled workflow, and the operator needs repository write access. Run the new workflow from **main**, entering the original tag. Workflow code comes from the chosen running ref; package source is checked out from the tag separately:

```bash
gh workflow run release.yml --repo Pegasus-Yang/Browscreen --ref main -f tag=v0.3.1
```

Use the Actions UI if GitHub CLI is unavailable. Historical 0.3.0/0.3.1 tags retain their original Chinese metadata: validation checks the README selected by that tag rather than applying new English rules retroactively. They cannot masquerade as the English metadata fix on PyPI. Inspect existing Releases/drafts before retrying; never overwrite them blindly.

## 5. Reuse Release files for a separate PyPI upload

The following gh command requires an installed and authenticated GitHub CLI. Alternatively download the four assets from the Release page or GitHub's official Releases API. Verify SHA256SUMS, manifest tag/source commit, English package metadata, strict checks, and fresh installations. Do not rebuild the same version from a main branch whose README has changed.

```bash
browscreen_release_dir=$(mktemp -d)
gh release download v0.3.2 --repo Pegasus-Yang/Browscreen --dir "$browscreen_release_dir"
(cd "$browscreen_release_dir" && shasum -a 256 -c SHA256SUMS)
```

First query `https://pypi.org/pypi/browscreen/0.3.2/json`. A missing version may be uploaded initially; an existing version requires exact filename and hash comparison. Uploaded filenames cannot be overwritten or reused after deletion. Do not move tags or rename old distributions to bypass this.

A token-free read-only rehearsal does not verify account permission or upload anything:

```bash
env -u UV_PUBLISH_TOKEN -u UV_PUBLISH_USERNAME -u UV_PUBLISH_PASSWORD \
  -u UV_PUBLISH_URL -u UV_PUBLISH_CHECK_URL -u UV_PUBLISH_INDEX \
  uv publish --no-config --dry-run --trusted-publishing never --keyring-provider disabled \
  --publish-url https://upload.pypi.org/legacy/ --check-url https://pypi.org/simple/ \
  "$browscreen_release_dir/browscreen-0.3.2-py3-none-any.whl" "$browscreen_release_dir/browscreen-0.3.2.tar.gz"
```

Upload only with authorization. uv does not automatically consume PYPI_TOKEN: map it to UV_PUBLISH_TOKEN in the child process only. Remove inherited username, password, URL/check URL/index settings from other registries and disable shell tracing. Never print, record, or send the token:

```bash
set +x
UV_PUBLISH_TOKEN="${PYPI_TOKEN:?Configure PYPI_TOKEN in the environment}" \
  env -u UV_PUBLISH_USERNAME -u UV_PUBLISH_PASSWORD \
  -u UV_PUBLISH_URL -u UV_PUBLISH_CHECK_URL -u UV_PUBLISH_INDEX \
  uv publish --no-config --trusted-publishing never --keyring-provider disabled \
  --publish-url https://upload.pypi.org/legacy/ --check-url https://pypi.org/simple/ \
  "$browscreen_release_dir/browscreen-0.3.2-py3-none-any.whl" "$browscreen_release_dir/browscreen-0.3.2.tar.gz"
```

If reloading an authorized shell profile, disable tracing and suppress its output, then disable tracing again. Never log the profile, token, or full environment. After an interruption, inspect official file lists first: matching existing files may be skipped; a differing hash must stop the upload.

## 6. Verify official JSON, simple indexes, and both files

Set the downloaded Release directory and run this code using the root `.venv`. It compares the original Release and PyPI files rather than equating identical filenames:

```bash
export BROWSCREEN_RELEASE_DIR="$browscreen_release_dir"
.venv/bin/python - <<'PY'
import hashlib,io,json,os,tarfile,zipfile
from email import policy
from email.parser import BytesParser
from pathlib import Path
from urllib.request import Request,urlopen

folder=Path(os.environ['BROWSCREEN_RELEASE_DIR']).resolve()
manifest=json.loads((folder/'release-manifest.json').read_text())
version=manifest['version'];expected=manifest['files']
assert manifest['release_tag']==f'v{version}'
def request(url,accept='application/json'):
    return Request(url,headers={'User-Agent':'browscreen-release-check','Accept':accept,'Cache-Control':'no-cache'})
with urlopen(request(f'https://pypi.org/pypi/browscreen/{version}/json'),timeout=30) as response:
    published=json.load(response)
info=published['info']
assert info['name']=='browscreen' and info['version']==version
assert info['description_content_type']=='text/markdown'
assert info['project_urls']['Documentation'].endswith('/doc/README.en.md')
assert {item['filename'] for item in published['urls']}==set(expected)
with urlopen(request('https://pypi.org/simple/browscreen/','application/vnd.pypi.simple.v1+json'),timeout=30) as response:
    simple=json.load(response)
indexed={item['filename']:item for item in simple['files']}
output=folder/'from-pypi';output.mkdir(exist_ok=True)
for item in published['urls']:
    name=item['filename'];digest=expected[name]
    assert not item['yanked'] and item['digests']['sha256']==digest
    assert indexed[name]['hashes']['sha256']==digest
    assert item['url'].startswith('https://files.pythonhosted.org/')
    with urlopen(request(item['url'],'application/octet-stream'),timeout=30) as response:
        content=response.read()
    assert hashlib.sha256(content).hexdigest()==digest
    assert content==(folder/name).read_bytes()
    (output/name).write_bytes(content)
    if name.endswith('.whl'):
        with zipfile.ZipFile(io.BytesIO(content)) as archive:
            raw=archive.read(f'browscreen-{version}.dist-info/METADATA')
    else:
        with tarfile.open(fileobj=io.BytesIO(content),mode='r:gz') as archive:
            raw=archive.extractfile(f'browscreen-{version}/PKG-INFO').read()
    metadata=BytesParser(policy=policy.default).parsebytes(raw)
    assert metadata['Version']==version and metadata['Summary']==info['summary']
    assert metadata['Requires-Python']==info['requires_python'] and metadata['License-Expression']=='MIT'
    assert metadata.get_payload(decode=True).decode('utf-8').strip()==info['description'].strip()
    assert info['summary'].isascii() and info['description'].startswith('# browscreen\n')
    assert 'A browser screenshot and mouse pointer preview service.' in info['description']
print(f'Official JSON/simple, both downloads, hashes and English metadata verified: {version}')
PY
```

Install the from-pypi wheel in another brand-new independent `.venv` and repeat base/video, CLI, Settings, resources, and MP4 checks. Keep source/workflow commits, Actions URL, tag, file hashes, upload results, and download/install evidence under ignored `local/releases/0.3.2/`.

Official JSON/simple/file verification, mirror synchronization, PyPI page rendering, and real-Chrome capture acceptance are separate layers. Aliyun may lag an initial upload; an HTTP 200 or client-verification page does not establish rendered-description acceptance. If the page cannot be read, report that boundary explicitly.
